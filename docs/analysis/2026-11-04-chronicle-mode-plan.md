# 年表模式規劃

日期：2026-11-04。狀態：AC-1～AC-9 已核准，尚未實作。規模：Medium。

## 目標

在現有地圖之外加一個「年表」顯示模式：同一份 `visibleEvents` 改以單欄編年列表呈現，事件卡可外連維基，兩種模式可隨時切換，篩選、搜尋、人物追蹤與詳情面板沿用。

## 核准來源

2026-11-04 對話中提出三項選擇，使用者回覆「好都依照建議」，核准：

1. 版面採單欄編年列表，不做小說泳道。
2. 年表模式保留底部時間軸，作為篩選與跳轉。
3. 維基連結只用 `sources` 既有的 zh.wikipedia 連結，不由人物名稱組網址。

同一則建議中的切換方式（`?view=chronicle` 與 store `viewMode`）、地圖隱藏不銷毀、卡片內容與手機驗收尺寸一併視為核准。

同日 Q1～Q3（見「已確認事項」）使用者皆選建議答案。

## 現況

- `app.routes.ts` 為空，沒有使用 Router；部署在 GitHub Pages 的 `/jymap/`，已有 `404.html`。
- 事件共 257 筆，朝代 6 個（春秋、北宋、南宋、元、明、清），66 個不同年份，同年最多 22 筆（1223 年）。
- 32 筆有 `eraEstimate`，屬 5 部作品。依 2026-10-31 的決定，`year` 只是排序佔位，不得對外顯示，也不參與同年判斷。其中《白馬嘯西風》的 `dynasty` 是「清」，但 `dynastyLabel` 是「朝代未定」、區間從 1465 年起；《俠客行》也是「朝代未定」。所以依 `dynasty` 欄位分段放推估事件會前後矛盾。
- 每筆事件至少有 1 個 zh.wikipedia 連結，不重複條目 107 個。104 筆事件的維基連結全部是作品頁；109 筆至少有一個連結的條目名稱等於該事件的人物。
- `onNavigateToEvent()`（搜尋結果、時間軸點）會把時間範圍設成事件前後 10 年；人物追蹤 `selectCharacter` 會把範圍設成人物事件前後 20 年，`visibleEvents` 仍包含範圍內所有事件。
- 小說顏色寫在 `MapContainerComponent.getNovelColor()`，是 private 方法。
- `app.component.scss` 已超過元件樣式預算 1.52 kB（見 [2026-11-02 行動版文件](2026-11-02-mobile-ux-pass.md)）。

## 驗收條件

**AC-1 切換**
1. 搜尋框旁有「地圖｜年表」切換鈕，以 `aria-pressed` 表示目前模式。
2. 切到年表時網址加上 `?view=chronicle`，切回地圖時移除；不新增瀏覽紀錄（`replaceState`），路徑保留 `/jymap/`。
3. 直接開啟或重新整理 `?view=chronicle` 會進入年表模式。

**AC-2 列表結構**
1. 年表顯示 `visibleEvents`，依朝代分段，段標題顯示朝代與件數。
2. 段內依年份分組，年份標題用 `getYearText()`（西元前顯示「西元前476年」）並顯示件數；同年事件依現有 `compareEventsByTime()` 排序。
3. 頂部有朝代跳轉列，捲動時固定；點朝代捲到該段。篩選後沒有事件的朝代不出現。

**AC-3 推估事件**
1. 有 `eraEstimate` 的事件不顯示 `year`，不併入任何年份組；顯示 `eraEstimate.label`、`getEventDynastyText()` 與「推估」標記。
2. 推估事件放在列表最後的「確年未詳」段，每部作品一組，組標題是推估區間與朝代文字，各組依區間起始年排序；朝代跳轉列最後也有「確年未詳」（Q3）。
3. 同作品的推估事件依 `storyOrder` 排序。

**AC-4 維基外連**
1. 卡片只顯示 `sources` 中 `zh.wikipedia.org/wiki/` 的連結，不由人物或標題組網址。
2. 連結分為三類：條目名稱正規化後（雕→鵰、传→傳，去掉「_(…)」與「角色列表」）等於某部小說名稱的為「作品」，等於該事件人物之一的為「人物」，其餘為「歷史・主題」。
3. 卡片先顯示「歷史・主題」與「人物」；兩者都沒有時才顯示「作品」連結，讓每張卡至少有一個維基連結。
4. 連結文字是解碼後的條目名稱（去掉消歧義括號），以 `target="_blank" rel="noopener"` 開新分頁。

**AC-5 事件卡**
1. 卡片顯示標題、年代、朝代、小說色標、人物、摘要（預設兩行，可展開）、維基連結與「在地圖上看」。
2. 點卡片打開現有的事件詳情面板；點小說標籤套用小說篩選；點人物進入人物追蹤。
3. 小說顏色與地圖標記一致（由同一份對照表提供）。

**AC-6 回到地圖**
1. 只切換模式時，切回地圖後縮放與中心不變，地圖沒有灰塊。
2. 點「在地圖上看」切回地圖、選中該事件並飛到該地點，結果與從地圖點選該事件相同。

**AC-7 共用功能**
1. 篩選條件列、「顯示 N 件事件」與空結果提示兩個模式共用，數字一致。
2. 年表模式保留底部時間軸：拖曳範圍會更新列表；點時間軸上的事件點，列表捲到該卡並高亮。
3. 切換模式算一步探索，「返回上一步」會還原上一個模式與條件。

**AC-8 年表中的搜尋與人物追蹤**
1. 年表模式點搜尋結果或時間軸事件點，不改時間範圍。事件不在目前列表時，解除擋住它的條件（小說篩選照現有方式顯示提示，時間範圍直接解除），再捲到該卡、高亮並打開詳情面板（Q1）。
2. 年表模式追蹤人物時，列表保留範圍內全部事件，該人物的事件高亮、其他淡化，並捲到該人物的第一筆（Q2）。
3. 點人物面板中的事件時，列表捲到該卡，不切換模式。

**AC-9 手機與品質**
1. 390×844、360×640、844×390 三種視窗截圖：切換鈕、朝代跳轉列、卡片與時間軸互不遮擋，沒有頁面橫向捲動，可點元素至少 44px。
2. 三種視窗沒有頁面錯誤。
3. `npm run test:ci`、`npm run test:mobile`、`npm run build` 通過；`app.component.scss` 的預算超出量不增加。

## 已確認事項

2026-11-04 使用者皆選建議答案。

| 編號 | 問題 | 答案 |
| --- | --- | --- |
| Q1 | 年表模式點搜尋結果（或時間軸事件點）時，要不要像地圖一樣把時間範圍縮到前後 10 年？ | 不縮。事件不在目前列表時，解除擋住它的條件（小說篩選照現有方式提示，時間範圍直接解除），再捲到該卡、高亮並開詳情面板。 |
| Q2 | 年表模式追蹤人物時，列表要只留該人物的事件，還是全部保留、標出該人物的事件？ | 全部保留，該人物的事件高亮、其他淡化，並捲到第一筆。這和地圖模式一致，人物年表本身已在人物面板。 |
| Q3 | 32 筆推估事件放哪裡？ | 列表最後獨立一段「確年未詳」，每部作品一組，組標題是推估區間與朝代文字，依區間起始年排序。因為《白馬》《俠客行》朝代未定，放進朝代段會和段標題矛盾。 |
