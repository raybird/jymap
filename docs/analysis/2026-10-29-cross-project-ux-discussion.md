# 跨專案使用體驗討論草案

日期：2026-10-29。狀態：根據四個專案的文件與部分原始碼整理，尚未取得其他 session 的回覆；本文件不是跨 session 共識。

## 已確認的 jymap 方向

以自由查找金庸世界為入口，讓人物與故事提供繼續探索的動機。使用者能查找、理解目前視野、延伸探索，並返回原先的位置。

## 四個專案的切入點

| 專案 | 依據 | 討論時帶入的觀點 |
| --- | --- | --- |
| jymap | 搜尋、小說篩選、人物年表與軌跡 | 人物／小說／事件的分類搜尋，跨小說探索，故事順序 |
| historical-map | README 的 schematics、集中設定與延伸模型 | 哪些互動已足夠穩定，適合由模板生成；哪些仍應由主題自行實作 |
| cap-map | README，以及地圖元件的手機焦點偏移與側欄樣式 | 手機側欄遮蔽、跨區域查找、事件理解與自我檢核 |
| 3S-5E | README、集中年代設定與事件模型 | 大跨度分期、文明主題探索，以及傳說年代／位置應如何表達 |

上述為文件與程式提供的討論線索，並非已完成的使用者研究結果。

## 建議共用的體驗

1. **查找入口**：搜尋範圍與目前地圖篩選分開表達。若搜尋目標被篩選排除，點選後必須讓目標可見，並說明哪些條件已改變。
2. **視野摘要**：呈現已套用的條件、時間範圍與結果數；每項可移除，也可一次重設。沒有結果時提供具體解除條件的入口。
3. **焦點同步**：點選同一事件後，地圖、時間軸與詳情一致；手機以實際面板占用的空間定位焦點。
4. **探索返回**：從搜尋到人物／主題再到另一事件，返回時恢復來源清單、篩選與視圖。
5. **延伸探索**：推薦項目標示原因，例如共同人物、同一地點或時間相近；關係不應只由年份排序推定。

## 應保留的主題差異

- jymap：作品、人物、小說情節與歷史背景，故事順序可能不同於年份順序。
- cap-map：課程範圍、科目圖層、考點與測驗；查找答案與練習作答的入口應清楚。
- 3S-5E：傳說、文獻與考古材料的區別，以及年代和地點的不確定性。具體分類需另依來源核實，不直接視為既有模型能力。
- historical-map：提供共用互動契約與可用的預設，不要求每個主題具備人物、測驗或相同內容欄位。

## 建議的討論順序

1. 用同一組操作情境比較四個實作：搜尋被篩選隱藏的事件、連續切換事件、手機開啟詳情、延伸探索後返回。
2. 每個 session 提出最影響自己使用者的三個問題，附實作位置或可重現步驟。
3. 對齊外部行為與驗證方式，再挑一個專案試作；實際確認好用後，才決定是否回納模板。

## 給其他 session 的討論邀請

> 2026-10-29 跨專案 UX 討論：使用者希望 jymap 以「自由查找」為入口，透過人物與故事延伸探索，並邀請 historical-map、cap-map、3S-5E 一起比較。請先只分析，不修改或部署。請根據自己的現有實作回覆：(1) 主要使用情境與三個 UX 痛點；(2) 可分享給其他專案的既有互動，附檔案位置；(3) 不適合共用的主題差異；(4) 對搜尋範圍、篩選摘要、手機焦點、探索返回的建議；(5) 建議最先試作的一項及可觀察的成功條件。請回覆到原 session，再由協調者整理，不把草案當成已核准實作。
